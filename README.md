# 冬日出走 · 旅行计划集

Render 上的旅行分享入口，首页并列提供乌鲁木齐和温州计划，并预留新增目的地位置。乌鲁木齐仍由服务器读取已有旅行管理页，保留原行程、官方依据和变更记录，不修改或搬迁原数据库。温州使用用户提交的5天4夜文字审核稿，明确区分参考价格、预算和待核实事项。

## 功能

- 查看每日行程、航班住宿、交通、预算、官方规则、怕冷替代方案与变更摘要。
- 温州提供完整分时行程、预约核实、餐厅预算和按天切换的路线地图。地图脚本和底图图片均从本站提供，含住宿区域、动车站与候船区域标记。
- 分享链接使用 `?plan=urumqi` 或 `?plan=wenzhou`；首页目的地清单在 `src/plans.ts`，新增计划时加入元数据并注册对应页面。
- 管理者在原管理页编辑。朋友无需 ChatGPT 账号即可打开分享页。
- 乌鲁木齐页面每分钟同步已保存的计划，支持手动刷新；温州是版本化审核稿。官方营业、雪季与预约信息不自动抓取或推断。
- 分享接口只接受 GET/HEAD。完整修改前后快照仅在原管理页保留，不提供给公开分享接口。
- 上游短暂不可用时明确标出上次同步时间；超过24小时的缓存不再展示。

## Render 配置

单个 Node.js Web Service，选择 Singapore、Free。构建命令 `npm ci --include=dev && npm run build`，启动命令 `npm start`。服务绑定 `0.0.0.0:$PORT`，健康检查 `/healthz`。无需额外 Render 数据库或磁盘。

在 Render 的 Environment 页面设置：

- `SOURCE_ORIGIN`：原旅行管理站点的 HTTPS origin，不带路径。
- `SOURCE_READ_TOKEN`：原站提供的服务器访问凭据，只保存在服务端。
- `MANAGE_URL`：原管理页的 HTTPS URL。
- `NODE_ENV`：`production`。

实际凭据、乌鲁木齐运行时数据和历史快照不进入 Git 仓库，也不进入浏览器脚本或日志。温州审核稿作为公开分享内容在源代码中版本化。不要把原站访问凭据嵌入前端。默认不允许搜索引擎索引；拥有分享链接的访客仍可以读取当前行程。

免费 Web Service 闲置后会休眠，首次重新访问可能稍慢。大陆网络能否访问应在上线后实测，不能以部署成功代替线路验证。
